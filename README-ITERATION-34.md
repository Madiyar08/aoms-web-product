# AOMS 2.0 — Iteration 34: Smart ATM cluster integrity

## Что изменено

- Уточнена географическая кластеризация остановок: новая точка включается в кластер только если находится в пределах порога от КАЖДОГО уже включённого ATM (complete-link), а не только от движущегося центроида.
- Устранено chain-merging: цепочка A—B—C больше не объединяет A и C в одну остановку, если расстояние между ними превышает 30 м.
- Добавлен `flattenClusterMemberIndexes()`: после оптимизации порядок кластеров раскрывается в исходные ATM, при этом все ATM одной физической остановки остаются подряд.
- Дубли индексов и некорректные номера кластеров безопасно игнорируются при раскрытии.
- Маршрутизация использует новый helper, сохраняя существующий Yandex API и локальную оптимизацию.

## Проверки

Команда: `node --experimental-strip-types --test tests/*.test.mjs`

Результат: **79/79 тестов пройдены**.

Добавлены тесты на объединение близких терминалов, непрерывность группы после перестановки кластеров, защиту от chain-merging, безопасное раскрытие индексов и некорректный порог.

## Ограничения

- Кластеризация остаётся географической (30 м); отдельного идентификатора Smart ATM-кластера в текущей модели ATM нет. Поэтому система не пытается угадывать бизнес-группы по названию или другим неподтверждённым признакам.
- Полный TypeScript check и `next build` не запускались: зависимости проекта не установлены в рабочем окружении.
- Production Railway, рабочая SQLite и Telegram не затрагивались.
