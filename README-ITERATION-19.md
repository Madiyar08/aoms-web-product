# AOMS 2.0 — Iteration 19

Персональные учётные записи административной панели.

## Вход после обновления

- Не удаляйте `ADMIN_PASSWORD` перед первым успешным входом.
- `ADMIN_PASSWORD` должен содержать не менее 12 символов.
- При первом входе приложение создаёт Super Admin в SQLite, если таблица `admin_users` ещё пуста.
- Логин берётся из `ADMIN_USERNAME`; если переменная не задана, используется `admin`.
- Для следующих входов используйте логин и пароль этой учётной записи.
- Можно задать отдельный `ADMIN_SESSION_SECRET`. Если он не задан, для подписи сессии используется `ADMIN_PASSWORD`.

## Пользователи и роли

В панели доступна страница `/users`:
- Super Admin — полный доступ и управление учётными записями.
- Operations Manager — операционные разделы и проверка инспекторских отчётов.
- Inspector — обзор и инспекторские отчёты.
- Viewer — ограниченный просмотр.

Пароли хранятся как salted scrypt-хеши. API не возвращает passwordHash. Удаление заменено отключением. Нельзя отключить последнего активного Super Admin.

## Обратная совместимость

Старые сессии, созданные через общий `ADMIN_PASSWORD`, временно принимаются как Super Admin. Поэтому не удаляйте `ADMIN_PASSWORD` сразу после обновления. После проверки персональных входов потребуется отдельный этап отключения legacy-входа.

## Ограничения

- Подписанная сессия действует 12 часов; отключение пользователя или смена роли не отзывает уже выданный токен мгновенно.
- Для немедленного завершения всех сессий смените `ADMIN_SESSION_SECRET` (или `ADMIN_PASSWORD`, если отдельный секрет не используется).
- Не все старые бизнес-server-actions прошли индивидуальный аудит разрешений. До production необходима staging-проверка каждого критичного действия и маршрута.
- Полная сборка Next.js/TypeScript и браузерная проверка в этой среде не выполнены из-за отсутствия установленных npm-зависимостей.
