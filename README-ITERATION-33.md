# AOMS 2.0 — Iteration 33: защита от двойного назначения ATM

## Что изменено

- Добавлен `lib/route-assignment.ts` с чистой проверкой пересечения ATM между маршрутами.
- При построении маршрута банкоматы, уже назначенные другому экипажу на ту же дату, исключаются из кандидатов.
- При пересчёте собственный маршрут не блокирует свои ATM.
- Перед записью результата выполняется повторная проверка внутри `withTransaction()` / `BEGIN IMMEDIATE`. Это закрывает окно гонки, пока внешний сервис оптимизации маршрута отвечает.
- Если конфликт появился во время оптимизации, новый результат не записывается; возвращается понятная ошибка с количеством конфликтующих ATM и датой.
- В карточке маршрута показывается количество ATM, уже назначенных другому экипажу.
- Добавлены unit-тесты на конфликт в тот же день, исключения для собственного назначения/другой даты и дедупликацию.

## Проверки

Команда: `node --experimental-strip-types --test tests/*.test.mjs`

Результат: **75/75 тестов пройдены**.

ZIP проверен через `unzip -t`.

## Ограничения проверки

- Полный TypeScript check и `next build` не запускались: зависимости проекта не установлены в рабочем окружении.
- Не выполнялись подключения к production Railway, GitHub, рабочей SQLite или Telegram.
- Защита от повторного назначения реализована на уровне маршрутов и транзакционного сохранения. Она не заменяет отдельную бизнес-проверку пересекающихся назначений в форме расписания.
