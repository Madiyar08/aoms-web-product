# Iteration 43 — atomic inspector media archive persistence

## Что изменено

- Подтверждение архивации медиа теперь сохраняет ссылку в `inspector_reports` и завершённость элемента в `inspector_media_queue` внутри одной SQLite-транзакции.
- Перед записью повторно читается актуальное задание очереди и отчёт; уже завершённый элемент не перезаписывается повторно.
- Локальный файл удаляется только после успешного commit транзакции.
- Добавлена проверка формата Telegram archive URL (`tg_` для фото, `tgvideo_` для видео).
- Перед заменой проверяется, что исходное фото/видео всё ещё связано с отчётом; несогласованность приводит к ошибке и retry, а не к потере ссылки.
- При ошибке обновления отчёта или очереди вся транзакция откатывается, локальный файл остаётся доступным для повторной обработки.
- Вынесено детерминированное построение перехода состояния в `inspector-media-queue-core.ts` для независимых тестов.
